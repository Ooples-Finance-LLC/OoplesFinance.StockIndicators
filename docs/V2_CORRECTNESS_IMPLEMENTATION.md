Tracking issue: https://github.com/Ooples-Finance-LLC/OoplesFinance.StockIndicators/issues/244

Implementation is in progress. This ledger does not mark the library-wide assurance plan complete.

## Adopted compatibility decisions

- V2 shared validation requires formula references by default. `IndicatorValidationOptions.Smoke()` explicitly opts into universal checks without complete formula coverage.
- Startup values must be finite unless an indicator implements `IIndicatorStartupContract` with a per-output NaN policy. Infinity is never an unavailable-value marker. Post-warmup outputs must be finite.
- The new reference overload takes `IndicatorErrorBudget` and checks startup by default. The tolerance overload also checks from bar zero; it is not evidence that its generic tolerance is appropriate for every output. Sign-sensitive contracts must require matching signs, including nonzero versus zero.
- Batch multi-series evaluation requires equal counts and identical strictly increasing timestamps. Unsupported alignment throws before state reset/update. Callers must align observations explicitly; the library does not impute or truncate them.
- Benchmark previews do not replace committed cached benchmark values. Final primary evaluation consumes the committed benchmark; preview snapshots are not committed observations.
- Rolling population deviation remains the approved definition for `StandardDevation.Std`, with the selected moving average controlling Signal.
- Native RSMK requires positive finite closes on both inputs. Shared paired validation injects invalid observations, checks rejection, and compares recovery with fresh and reset trajectories. Customer domain declarations use the same path. Additional replay fixtures are now exercised by both validators.
- V2 streaming default outputs now agree with generated/fast defaults: `FastEdo` for EhlersDecyclerOscillatorV1 and `UpperBand` for VortexBands. Named outputs remain available.
